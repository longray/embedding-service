## 2. 通信协议

### 2.1 发信规则

**文件命名**:
```
D:\mailbox\{target-team}\{from}_to_{to}_YYYY-MM-DD_{sequence}.md
```

**文件格式**:
```markdown
# {发件人}致{收件人} — {主题}

**发件人**: {角色} (Port {端口})  
**收件人**: {角色} (Port {端口})  
**日期**: YYYY-MM-DD  
**主题**: {主题}

---

## 正文

内容...

---

**{发件人}**  
Agent {X} (Port {YYYY})  
YYYY-MM-DD
```

### 2.2 收信规则

**检查频率**: 每 5 分钟

**检查步骤**:
1. 列出 `D:\mailbox\{my-team}\` 目录
2. 按时间排序，找出最新文件
3. 检查是否已读（维护已读列表）
4. 读取未读邮件
5. 解析邮件内容
6. 生成响应

### 2.3 响应规则

**响应时间**: 收到邮件后 5 分钟内

**响应类型**:

| 收到邮件类型 | 响应动作 | 示例 |
|--------------|----------|------|
| INFO | 记录信息，无需回复 | "任务已完成" |
| REQUEST | 必须回复，提供所需信息 | "请确认参数" → "参数确认如下..." |
| CONFIRM | 可选回复，确认收到 | "收到确认" |
| ALERT | 立即响应，解决问题 | "发现不一致" → "立即修复..." |

## 3. 状态机

### 3.1 状态定义

```
IDLE: 空闲，等待事件
CHECKING: 检查邮箱中
READING: 读取邮件中
PROCESSING: 处理邮件中
SENDING: 发送回复中
REVIEWING: 联合评审中
```

### 3.2 状态转换

```
IDLE → CHECKING: 每 5 分钟触发
CHECKING → READING: 发现新邮件
CHECKING → IDLE: 无新邮件
READING → PROCESSING: 邮件解析完成
PROCESSING → SENDING: 需要回复
PROCESSING → IDLE: 无需回复
SENDING → IDLE: 邮件发送完成
IDLE → REVIEWING: 收到评审邀请
REVIEWING → SENDING: 评审完成，发送纪要
```

## 4. 自动评审流程

### 4.1 评审触发条件

- 收到 `/start-review` 指令
- 或收到评审邀请邮件
- 或达到预定评审时间

### 4.2 评审流程

```
阶段 1: 准备确认（5 分钟）
├── 检查双方准备度
├── 确认文档完整性
├── 确认参数对齐
└── 发送评审开始通知

阶段 2: 逐项评审（40 分钟）
├── WebSocket 协议评审（20 分钟）
│   ├── 心跳机制确认
│   ├── ACK 机制确认
│   ├── 重连策略确认
│   └── DIFF 模式确认
├── Precompute API 评审（15 分钟）
│   ├── 端点确认
│   ├── 数据格式确认
│   └── 性能参数确认
└── 开发计划对齐（5 分钟）
    ├── Phase 2-3 确认
    ├── 里程碑确认
    └── 风险识别

阶段 3: 结果确认（10 分钟）
├── 汇总评审结果
├── 确认关键决策
├── 分配行动项
└── 发送会议纪要

阶段 4: 自动推进（5 分钟）
├── 更新 BACKLOG
├── 创建开发任务
├── 设置提醒
└── 发送执行通知
```

### 4.3 评审输出

## 5. 用户指令

### 5.1 /start-collaboration

**功能**: 启动自主协作模式

**效果**:
- Agent A 和 Agent B 开始自主通信
- 自动检查邮箱、发送邮件
- 自动推进项目
- 用户只需在关键节点确认

### 5.2 /start-review

**功能**: 启动联合评审

**效果**:
- 自动进入评审模式
- 按议程逐项评审
- 自动生成会议纪要
- 自动分配行动项

### 5.3 /status

**功能**: 查看协作状态

**输出**:
- 当前状态
- 未读邮件数量
- 待办任务列表
- 项目进度

### 5.4 /pause

**功能**: 暂停协作

**效果**:
- 暂停自主通信
- 等待用户指令
- 保留当前状态

### 5.5 /resume

**功能**: 恢复协作

**效果**:
- 恢复自主通信
- 继续推进项目

## 6. 安全与边界

### 6.1 安全规则

- 不执行破坏性操作（删除、修改对方文件）
- 不访问对方代码库
- 只通过 Mailbox 通信
- 所有操作记录日志

### 6.2 边界条件

- 邮件大小限制：1MB
- 响应时间限制：5 分钟
- 重试次数：3 次
- 超时处理：通知用户

### 6.3 人工介入

以下情况需要人工介入：
- 双方无法达成一致
- 发现重大风险
- 需要用户决策
- 系统错误

## 7. 示例场景

### 场景 1: 任务完成通知

```
Agent B 完成任务 → 自动生成邮件 → 发送到 Agent A 邮箱
Agent A 收到邮件 → 解析内容 → 记录完成状态 → 发送确认回复
```

### 场景 2: 发现问题

```
Agent A 发现问题 → 自动生成问题报告 → 发送到 Agent B 邮箱
Agent B 收到邮件 → 解析问题 → 修复问题 → 发送修复通知
Agent A 收到通知 → 验证修复 → 发送确认
```

### 场景 3: 联合评审

```
用户: /start-review
Agent A: 检查准备度 → 发送评审邀请
Agent B: 收到邀请 → 确认准备度 → 发送确认
Agent A: 开始逐项评审 → 发送评审项
Agent B: 响应评审项 → 发送确认
...
Agent A: 生成会议纪要 → 发送给双方
Agent B: 收到纪要 → 确认
```
