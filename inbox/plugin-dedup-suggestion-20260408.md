# 致后端团队：代码分析数据去重策略建议

**发件人**: OpenCode Memory Plugin (插件端) 团队  
**日期**: 2026-04-08  
**主题**: 建议代码分析数据跳过去重检查  

---

## 1. 问题背景

联调过程中发现：代码分析数据上传后被跳过（reason: 'hash'），但查询不到。

### 现象

```json
// 上传响应
{
  "total": 1,
  "success": 0,
  "failed": 0,
  "skipped": [{
    "local_id": null,
    "existing_id": "memory:ihvclhn43qeqkg3f3twt",
    "reason": "hash",
    "similarity": null
  }]
}

// 查询结果
GET /api/v1/memories/memory:ihvclhn43qeqkg3f3twt
// 返回: {"detail":"记忆不存在"}
```

**矛盾点**:
- 去重检测认为数据已存在（跳过上传）
- 但实际查询不到该记忆

---

## 2. 问题分析

### 可能原因

#### 原因 A: 去重检测与实际存储不一致

**流程**:
```
1. 计算 hash
2. 检查 hash 是否已存在 → 存在（跳过）
3. 但实际记忆数据丢失
```

**结果**: 去重通过，但数据不存在

#### 原因 B: 代码分析数据被错误去重

**场景**:
- 代码文件内容相同（如模板代码）
- 不同项目、不同文件的代码被去重
- 导致只有第一个上传成功，后续都被跳过

#### 原因 C: 写入失败但去重记录保留

**流程**:
```
1. 第一次上传 → 写入失败（但 hash 已记录）
2. 第二次上传 → 检测到 hash → 跳过
3. 实际数据不存在
```

---

## 3. 建议方案

### 方案 1: 代码分析数据跳过去重（推荐）

**建议**:
- `type: "code"` 的记忆不参与去重检查
- 每次代码分析都创建新的记忆条目
- 通过 `source_id` 或 `file_path` 关联版本

**优点**:
- 代码文件每次分析都是独立的
- 支持代码版本追踪
- 避免不同项目代码冲突

**实现**:
```python
def should_deduplicate(memory):
    if memory.get('type') == 'code':
        return False  # 代码分析跳过去重
    return True  # 其他类型正常去重
```

---

### 方案 2: 基于文件路径去重

**建议**:
- 代码分析数据使用 `(project_id, file_path)` 作为去重键
- 同一文件多次分析视为更新，而非跳过

**优点**:
- 同一文件更新时覆盖旧数据
- 不同文件即使内容相同也不冲突

**实现**:
```python
def get_dedup_key(memory):
    if memory.get('type') == 'code':
        return (memory['project_id'], memory['metadata']['file_path'])
    return memory['content_hash']  # 其他类型用 hash
```

---

### 方案 3: 修复去重检测与实际存储的一致性

**建议**:
- 去重检测时同时检查数据是否真实存在
- 如不存在，允许重新上传

**实现**:
```python
def check_duplicate(hash):
    memory_id = hash_index.get(hash)
    if memory_id:
        # 验证数据真实存在
        if db.query(f"SELECT id FROM memories WHERE id = '{memory_id}'"):
            return True  # 确实存在，跳过
        else:
            # 记录不一致，删除索引
            del hash_index[hash]
            return False  # 允许重新上传
    return False
```

---

## 4. 推荐方案

**首选: 方案 1（代码分析跳过去重）**

理由:
1. 代码分析的本质是版本追踪，不应去重
2. 同一文件多次分析应保留历史
3. 不同项目相同代码应独立存储
4. 实现简单，无需复杂逻辑

**备选: 方案 2（基于路径去重）**

如需要覆盖更新，可使用方案 2。
