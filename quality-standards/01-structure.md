## 2. 优先级体系 (P0-P5)

# Src: docs/01-GLOBAL-PRINCIPLES.md#1.2.3

### 2.1 安全等级定义

| 优先级 | 类型 | 说明 | 处理方式 | 示例 |
|--------|------|------|----------|------|
| **P0** | 必须通过 | 密钥泄露、SQL注入 | **阻断提交/部署** | Gitleaks检测到密钥 |
| **P1** | 强烈建议 | 高危漏洞、类型错误 | **阻断提交** | Bandit高危漏洞、Pyright错误 |
| **P2** | 建议修复 | 中危漏洞、代码质量 | **自动修复** | Ruff --fix可修复的问题 |
| **P3** | 可选修复 | 低危问题、代码风格 | **仅警告** | 复杂度警告、命名建议 |

### 2.2 本项目优先级映射

**P0 级别（阻断提交）**:
- Gitleaks 密钥泄露检测
- Bandit 安全扫描（高危）

**P1 级别（阻断提交）**:
- Pyright 类型检查错误
- Ruff Check 严重错误（F401未定义变量等）
- Pytest 测试失败（pre-push阶段）

**P2 级别（自动修复）**:
- Ruff Format 格式化
- Ruff Check --fix 可修复问题
- 导入排序（isort）

**P3 级别（仅警告）**:
- 复杂度警告（McCabe > 15）
- 函数长度警告（> 50行）
- 代码风格建议

## 3. 核心原则

# Src: docs/01-GLOBAL-PRINCIPLES.md#1.2

### 3.1 自动化优先

**原则**: 所有检查通过工具自动执行，禁止手动操作

**实施**:
- Pre-commit hooks 自动运行所有检查
- CI/CD pipeline 自动验证
- 修复自动化：`ruff --fix`、`pytest --tb=short`

### 3.2 统一性

**原则**: 全项目使用相同工具链和配置

**实施**:
- 工具统一：Ruff (format + lint)、Pyright、pytest
- 配置统一：pyproject.toml 集中管理
- 风格统一：line-length=120、Python 3.10+

### 3.3 性能优先

**原则**: 增量检查、缓存策略、并行执行

**实施**:
- Pre-commit 增量检查（仅变更文件）
- Ruff 缓存（.ruff_cache/）
- 目标性能：增量检查 < 5s，全量检查 < 30s

### 3.4 安全性

**原则**: 密钥防护、代码安全、依赖安全

**实施**:
- Gitleaks 密钥检测（P0）
- Bandit Python 安全扫描（P0-P1）
- 依赖审计：pip-audit（计划中）

## 4. 团队规模适配

# Src: docs/01-GLOBAL-PRINCIPLES.md#1.1.3

**本项目定位**: 小型团队 (2-5人)

**适用流程**:
- ✅ 格式化 + Lint + 类型检查（Level 2: 第2-4章）
- ✅ 安全扫描 + 测试（Level 2: 第5-6章）
- ✅ Pre-commit + CI/CD（Level 3: 第7-8章）
- ⚠️ Code Review 简化流程（个人项目可用自动化替代）

**简化策略**:
- 个人开发：自动化检查替代人工审查
- 2-3人团队：交叉审查，至少1人Approve
- 紧急修复：事后补充审查
