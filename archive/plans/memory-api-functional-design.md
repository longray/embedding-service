## 一、功能概述

### 1.1 产品定位

记忆管理系统是包装层服务的核心功能模块，为用户提供智能记忆存储、检索和知识图谱构建能力。系统通过向量化技术和图数据库，实现语义级别的记忆管理。

### 1.2 核心价值

1. **智能存储**: 自动将文本记忆转换为向量表示，支持语义搜索
2. **知识图谱**: 自动提取实体和关系，构建结构化知识网络
3. **混合搜索**: 结合向量搜索和关键词搜索，提供最佳检索效果
4. **统一监控**: 集成健康检查，实时监控所有服务状态

### 1.3 目标用户

- AI应用开发者
- 知识管理系统构建者
- 需要语义搜索能力的应用

## 三、功能详细设计

### 3.1 健康检查功能 (F1)

#### 3.1.1 功能描述

提供统一的健康检查接口，监控所有依赖服务的状态。

#### 3.1.2 检查项

1. **包装层服务**
   - 检查项：服务运行状态、内存使用、CPU使用
   - 判断标准：进程存活即为健康

2. **Embedding服务**
   - 检查项：HTTP连接、响应时间
   - 判断标准：能够成功连接且响应时间 < 5s

3. **LLM服务**
   - 检查项：HTTP连接、响应时间
   - 判断标准：能够成功连接且响应时间 < 5s

4. **SurrealDB**
   - 检查项：WebSocket连接、查询响应
   - 判断标准：能够成功连接且查询响应时间 < 1s

#### 3.1.3 状态定义

- `healthy`: 所有服务正常
- `degraded`: 部分服务异常但核心功能可用
- `unhealthy`: 核心服务异常，功能不可用

#### 3.1.4 交互流程

```
用户 → GET /api/health
         ↓
    并行检查所有服务
         ↓
    汇总检查结果
         ↓
    返回健康状态
```

### 3.2 记忆上传功能 (F2)

#### 3.2.1 功能描述

批量上传记忆，自动生成向量、提取实体、构建关系。

#### 3.2.2 处理流程

```
用户提交记忆列表
    ↓
验证输入格式
    ↓
分批处理（batch_size=10）
    ↓
对每批记忆：
    1. 提取文本内容
    2. 调用Embedding服务生成向量
    3. 提取实体信息
    4. 存储记忆到SurrealDB
    5. 存储实体到SurrealDB
    6. 构建实体关系
    ↓
汇总处理结果
    ↓
返回上传统计
```

#### 3.2.3 实体提取规则

**提取方法**:
- 用户显式提供实体列表
- 未来可扩展：使用NER模型自动提取

**实体结构**:
```json
{
  "name": "实体名称",
  "type": "实体类型",
  "attributes": {
    "key": "value"
  }
}
```

**实体类型**:
- `person`: 人物
- `place`: 地点
- `organization`: 组织
- `concept`: 概念
- `event`: 事件
- `custom`: 自定义类型

#### 3.2.4 关系构建规则

**关系类型**:
1. **CONTAINS** (记忆→实体)
   - 记忆包含的实体
   - 自动创建

2. **RELATED_TO** (实体→实体)
   - 同一记忆中的实体
   - 自动创建

3. **SIMILAR_TO** (记忆→记忆)
   - 向量相似度 > 0.9 的记忆
   - 可选创建（性能考虑）

#### 3.2.5 错误处理

**部分失败策略**:
- 继续处理其他记忆
- 记录失败原因
- 返回成功和失败统计

**失败场景**:
- Embedding服务超时
- 向量维度不匹配
- 数据库写入失败
- 实体格式错误

### 3.3 记忆搜索功能 (F3)

#### 3.3.1 功能描述

提供多模式搜索能力，支持向量搜索、关键词搜索、混合搜索。

#### 3.3.2 搜索模式

**1. 向量搜索 (vector)**

```
查询文本
    ↓
生成查询向量
    ↓
SurrealDB KNN搜索
    ↓
返回Top-K结果
```

**特点**:
- 语义相关性搜索
- 不依赖关键词匹配
- 适合模糊查询

**2. 关键词搜索 (keyword)**

```
查询文本
    ↓
SurrealDB全文搜索
    ↓
BM25排序
    ↓
返回Top-K结果
```

**特点**:
- 精确关键词匹配
- 快速响应
- 适合精确查询

**3. 混合搜索 (hybrid)**

```
查询文本
    ↓
并行执行：
  - 向量搜索
  - 关键词搜索
    ↓
RRF算法融合结果
    ↓
返回Top-K结果
```

**特点**:
- 综合最佳效果
- 平衡语义和精确匹配
- 推荐默认模式

#### 3.3.3 过滤条件

支持的过滤字段：
- `tags`: 标签列表
- `type`: 记忆类型
- `source`: 来源
- `created_after`: 创建时间起始
- `created_before`: 创建时间结束

#### 3.3.4 结果排序

**排序依据**:
- 向量搜索：余弦相似度（降序）
- 关键词搜索：BM25分数（降序）
- 混合搜索：RRF分数（降序）

**相似度阈值**:
- 默认：0.7
- 范围：0.0 - 1.0
- 过滤低于阈值的结果

## 四、数据模型

### 4.1 记忆数据模型

```json
{
  "id": "memory:uuid",
  "content": "记忆文本内容",
  "embedding": [0.1, 0.2, ..., 1024维],
  "metadata": {
    "type": "knowledge|conversation|note",
    "source": "user_input|import|api",
    "tags": ["tag1", "tag2"],
    "language": "zh|en",
    "author": "user_id"
  },
  "entities": ["entity:id1", "entity:id2"],
  "created_at": "2026-03-03T17:00:00Z",
  "updated_at": "2026-03-03T17:00:00Z"
}
```

### 4.2 实体数据模型

```json
{
  "id": "entity:uuid",
  "name": "实体名称",
  "type": "person|place|organization|concept|event|custom",
  "attributes": {
    "description": "实体描述",
    "aliases": ["别名1", "别名2"],
    "custom_field": "自定义值"
  },
  "created_at": "2026-03-03T17:00:00Z"
}
```

### 4.3 关系数据模型

```json
{
  "id": "relation:uuid",
  "in": "entity:id1",
  "out": "entity:id2",
  "type": "CONTAINS|RELATED_TO|SIMILAR_TO",
  "properties": {
    "weight": 0.95,
    "context": "关系上下文"
  },
  "created_at": "2026-03-03T17:00:00Z"
}
```
